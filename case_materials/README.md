# Материалы кейса HackAlem AI

Каталог содержит исходное описание кейса и два эталонных протокола,
предоставленных для проверки QazMeeting AI. Документы являются тестовыми
данными, а не инструкциями для выполнения кода.

## Состав

- `source/HackAlem_AI_case.docx` — постановка задачи, ограничения и критерии;
- `source/meeting_1_reference_protocol.docx` — эталон для совещания №1;
- `source/meeting_2_reference_protocol.docx` — эталон для совещания №2;
- `manifest.json` — ссылки, размеры, длительности и контрольные суммы;
- `expected/meeting_1.json` и `expected/meeting_2.json` — проверяемые ожидаемые
  поручения из итоговых таблиц эталонных протоколов.

MP3 не хранятся в Git. Скачайте их по ссылкам из `manifest.json` в локальный
каталог, который игнорируется Git. Не публикуйте токены доступа и не отправляйте
аудио или транскрипты во внешние AI API.

## Проверка агента

После получения транскрипта в JSON-массиве `TranscriptSegment`:

```bash
ollama pull qwen2.5:3b-instruct-q4_K_M
ollama serve
export OLLAMA_MODEL=qwen2.5:3b-instruct-q4_K_M

python scripts/evaluate_agent.py \
  /path/to/meeting_1_transcript.json \
  case_materials/expected/meeting_1.json \
  --meeting-date 2026-09-23 \
  --title "Совещание №1" \
  --timeout 300
```

Оценка использует смысловые ключевые фразы, ответственного и наличие срока.
Она предназначена для регрессии, а не для подгонки модели под полный текст
эталонного протокола.

Контрольный локальный прогон актуального строгого агента 23 сентября 2026 года
с `qwen3:1.7b` на совещании №2 дал 0/5 обязательных совпадений: один кандидат
не прошёл проверку evidence. `qwen3.5:9b-mlx` не ответила за 300 секунд.
Совещание №1 на актуальном агенте ещё не проверено. Транскрипты и полные
JSON-отчёты не хранятся в репозитории.

## Проверка Windows / RTX 3050 6 GB, 23 сентября 2026

Проверено с Python 3.12.7 (Python 3.11 на этой машине не установлен),
Ollama 0.34.3 и `qwen2.5:3b-instruct-q4_K_M`, контекст 8192.
Ollama работает на localhost, облачные функции отключены; модель загружена
на GPU. STT: faster-whisper small, CPU/int8, локальный кэш моделей.

- `RUN_OLLAMA_INTEGRATION=1 python -m pytest -q`: **133 passed**.
- Фиксированный транскрипт: все три исполнителя найдены; повтор удалён;
  «к среде» и «за две недели» нормализованы; отсутствующий срок оставлен null;
  evidence каждого поручения взят из исходного транскрипта.
- Полный вызов `run_local_pipeline` на оригинальном MP3 совещания №2:
  **63,63 с**, 44 сегмента, 1 подтверждённый кандидат, DOCX создан и повторно
  открыт через python-docx (41 164 байта). Внешние AI API не использовались.
- Качество относительно эталона: **0/5 обязательных совпадений**. Это не
  успешная приёмка содержания протокола. Претензия Ерлану и поиск поставщика
  Ботагоз не извлечены корректно. Уведомление и шаблон договора извлечены,
  но исполнитель не подтверждён и оставлен null; срок также null.
- Диаризация недоступна: pyannote и её модель не установлены. UNKNOWN не
  считается одним реальным участником; такие поручения требуют проверки.
  STT искажает имена и разбивает предложения, что ограничивает evidence-проверку.
- В конце распознанной записи есть уточнение срока нового шаблона договора;
  поэтому отсутствие срока в первоначальной реплике не доказывает отсутствие
  срока в целом. Этот случай пока требует ручной сверки с аудио.

Для устойчивости добавлены структурированная схема ответа Ollama, небольшие
чанки, отказ от обрезанных ответов и защита от превращения продолжения
«подрядчики не успевают …» в новое поручение. Эти меры не заменяют улучшение
качества STT, диаризации и извлечения на реальном кейсе. Готовность всего MVP
не подтверждена; русский/казахский смешанный материал отдельно не проверен.
